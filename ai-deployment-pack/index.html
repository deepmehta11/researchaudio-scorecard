Seven working days

Turn uncertainty into a go, pilot, or stop.

Do not stretch this into a quarter-long “AI strategy” exercise. Each day closes one class of uncertainty and produces evidence another person can inspect.

Day 1 — name the decision

Choose one user outcome, one baseline, one owner, and one date. If the decision cannot be written in a sentence, the evaluation is not scoped.

Day 2 — establish task fit

Define the observable target, usable error signal, execution boundary, and the premise changes that require a human decision.

Day 3 — price success

Include retries, failure probability, attached calls, review labor, fixed costs, and the denominator that matters: a successful task or resolved case.

Day 4 — reproduce the claim

Run representative inputs against the exact model, prompt, tools, data permissions, and runtime you intend to deploy. Preserve failures, not only wins.

Day 5 — attack the loop

Test termination, budgets, prompt injection, tool permissions, recovery, observability, and human escalation before adding more capability.

Day 6 — rehearse rollback

Specify the launch cohort, monitoring window, rollback owner, rollback trigger, and the manual fallback that keeps the user outcome available.

Day 7 — make the decision

Mark every gate pass, fail, or unknown. Ship only when the evidence supports it; pilot when risk is bounded; stop when the premise or economics failed.
